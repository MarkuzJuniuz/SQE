# Theatre packs

Everything that belongs to one DCS map is data in a JSON file, not code. The bundled packs are the Caucasus (`sqe/data/theatres/caucasus.json`) and Syria 2001 (`syria.json`: the Hatay coast road, a midnight start, an opening strike on the SA-5 batteries). `.claude/crew-chief-internal/tools/geo_from_ne.py` makes a pack's map file (`<id>_geo.json`) from the public-domain Natural Earth shapefiles.
To add a theatre, write a pack and put it in `%APPDATA%\SQE\theatres\<id>.json` (a pack with the same id as a bundled one replaces it).
The New Campaign window shows a Theatre picker as soon as there is more than one pack. A campaign remembers its theatre.

SQE does not ship maps or ED data: a pack only names things DCS already has (airfield names from pydcs's terrain table) and holds your own numbers.
You still need the map installed in DCS to fly it, and pydcs must know the terrain (the `dcs_terrain` value is a class name in `dcs.terrain`).

## What a pack holds

| Key | Meaning |
|---|---|
| `id`, `name` | file name stem and the label in the picker |
| `dcs_terrain` | pydcs terrain class, e.g. `Caucasus` |
| `lat`, `lon`, `tz` | sun times and local time (`tz` = hours from UTC) |
| `temp_c` | 12 monthly mean temperatures for the mission weather |
| `geo` | coarse coastline / lakes / borders file for the map view (file in the same folder; `land`, `lakes`, `borders` as lists of [x, y] points, x north, y east, metres) |
| `scan` | required. The terrain-scan settings: `file` (the scan's file name in `Saved Games\SQE`), the area `x0 x1 y0 y1` in metres, `step`, and `probe_airport`. Optional: `height_step` and `relief_file`. A scan is not needed to play: the pack folder can ship the results (see "Data files" below) |
| `carrier` | `id`, `name`, optional `short` (the label), and the station: `from_airport`, `heading` and `distance_m` out to sea. Optional `carrier_band_km` (80: how far from the best station the seeded pick may range) and `carrier_evade_nm` (215: how far from every enemy airfield the fleet sails on a staged raid). Optional `carrier_standoff_nm`: how far the fleet stays from every enemy airfield |
| `blue_fields` | friendly airfields: `id`, `name`, `airport` (the pydcs airport name); optional `"divert": true` = a landing and recovery field with no squadron |
| `support_base` | optional. Blue field id that hosts the AWACS and tankers |
| `red_fields` | enemy airfields: `id` (must start with `ab_`), `name`, `airport`, `value` |
| `red_extra_airports` | optional. Airport names that are set red in every mission although they are not campaign fields |
| `painted_airports` | optional `{"blue": [...], "red": [...]}`: airport names (pydcs) painted friendly or enemy in every mission when they are not SQE bases, so no field is left neutral for any jet to land on. Mission-only, no campaign asset |
| `red_keep` | for a campaign level, the only enemy airfields that exist (`{"1": ["ab_a", "ab_b"]}`) |
| `wing_weight` | which enemy fields get an air wing, and how big a share |
| `field_tier` | depth of each enemy airfield, 1 front to 4 deep. Depth is data only: it no longer gates what can be tasked |
| `bomber_base` | enemy airfield for the strategic bomber wing (or empty). A bomber base that is not in `wing_weight` has no air wing at a level whose `bomber_wing` is 0: SQE plans no runway job for it |
| `bomber_bases` | optional list of red field ids, the lead first (Syria: `["ab_damascus", "ab_bassel"]`). The strategic bomber wing is split between these fields as evenly as possible (the level's `bomber_wing` and `bomber_escort_wing` are totals: 20 and 12 become 10 + 10 and 6 + 6), except that a field never holds more Tu-22M3 than it has stands for (DCS parking count): the overflow goes to the next field in the list with room, and what no field can park stays with the lead (Syria: 14 at Damascus and 6 at Bassel Al-Assad). Each field's Tu-22M3 and escort squadrons joining the field's own wing. The carrier raid and the Tu-22M3 land strike draw from every one of these fields that is open (a cut or destroyed field is skipped). Default: just `bomber_base` |
| `red_roster` | optional. `{"1": {"MiG_21Bis": 30, ...}, "2": ..., "3": ...}`: the jets of each aircraft type red has at that level, shared out over the fields by `wing_weight` and the parking (every field with a wing should get jets). A level without an entry uses SQE's own Caucasus roster (`redroster.ROSTERS`) |
| `level_overrides` | optional. `{"3": {"bomber_wing": 16, "bomber_escort_wing": 8}, ...}`: fields of the level's Difficulty (see `sqe/difficulty.py`) that differ in this theatre, e.g. the strategic bomber wing and its escorts. A field name SQE does not know is refused when the pack loads |
| `win_supply` | optional. `{"2": {"below": 0.40, "days": 3}, "3": {...}}`: a level that is won when the enemy's Force Index (its supply) is at or below `below` on `days` consecutive nights, with the pack's `win` story beat. Levels without an entry keep the ground victory (their `front.victory` bases) or, with none, the old air and command win; the Overview shows how close the collapse is in words. Default none |
| `works` | optional. Special blue targets and a second way to win (Syria's Lutorin works): `{"label": "Lutorin Works", "damage": 1.0, "levels": {"2": {"push": 2.0, "rebuild_days": 30, "supply_total": 25}, "3": {...}}, "sites": [{"id": "wks_name", "name": "...", "x": 0, "y": 0, "value": 10, "tier": 4}]}`. The sites (ids start `wks_`, DCS metres) are placed as depot-type targets at the levels listed in `levels`; they count as red supply sites in the Force Index (a level's optional `supply_total` is the whole count, works included: the road sites are drawn only up to it, so 12 fixed sites + 5 works + 8 road sites = 25), their own rebuild team mends them (the nightly supply repair does not), a strike does `damage` of a depot's damage (a level entry may set its own), one rebuild team rebuilds one destroyed works at a time (about `rebuild_days`), and red's push on the front grows by `push` x (works standing / works built). All of them destroyed at once wins the war; each listed level's story needs the beat `works_win` (`works_down` and `works_back` are optional). Default none |
| `start_hour` | optional. The hour Day 1 starts (0, 4, 8, 12, 16 or 20; turns are four hours). Default 8. A start at 0 makes Day 1 six turns long and its first two night turns; the campaign remembers it |
| `opening_strike` | optional. `{"levels": [2, 3], "kill": "sa5", "text": "...", "fill": ["SA-10", "EWR"]}`: at those levels every red site of the SAM variant `kill` starts the campaign destroyed (a scripted strike before the first mission), with the war-log line `text` (default "At midnight F-117A Nighthawks struck the long-range SA-5 batteries: every one is down" plus ", along with some SA-10 sites and early-warning radars" for the `fill` kinds actually hit, no counts; `{kill}` stands for the variant). They come back by the normal rebuild rule (5 to 7 days, half strength). Sites of other variants stay, except what `fill` (optional, S104d) names: the theatre's F-117A squadron flies the strike as pairs, one pair per target, the `kill` sites first, and each pair left over (ready jets / 2) takes the next site of the `fill` kinds in turn (an SA variant or `"EWR"`), deepest first, then farthest from the squadron's base. The jets are out of the squadron at the start (returning, then in refit) and each struck site gets a war-log line. With no F-117A squadron the script just kills the `kill` sites |
| `raid_attack_types` | optional list of red aircraft types (pydcs class names). The cheap attack type(s) that lead red's raids on troops, garrisons and supply sites (the unescorted supply raid and the 12,000 ft raid altitude follow them). Default `["Su_25"]` |
| `raid_bomber_types` | optional list. The bomber type(s) that fly field raids and are the only ones to fly the Kh-59M raids (they need those stores) and the Kh-31P SEAD packages; an attack type that carries the Kh-58U (the Su-17M4) flies SEAD too, always as a Kh-58U package. Default `["Su_24M"]`. A type may not be in both lists |
| `front.air_fields` | optional list. The red field keys (the id without `ab_`) whose belts count as the "MOUNTAIN" air-superiority front. Default: the Caucasus list (mozdok, beslan, nalchik, maykop, minvody, krymsk, gelen) |
| `front.defeat_bases` | optional whole number. How many fallen blue airfields lose the campaign. Default 3 |
| `nav` | optional. `{airport name: kneeboard line}`: the approach aids printed for a home or divert field (ILS, TACAN, NDB, VOR). A pack with the key replaces the Caucasus table; airports missing from it print nothing |
| `ils_runway` | optional. `{airport name: runway number}`: the runway end each ILS belongs to. A pack with the key replaces the Caucasus table |
| `mag_var_deg` | optional number, east positive. Magnetic variation used to turn runway numbers into true headings (crater visuals). Default 6.0 (Caucasus) |
| `extra_sams` | optional list. Fixed SAM sites placed in the new campaign after the per-field sites, on their own random stream, at the places the pack gives (they stay exactly there). Each: `id` (unique, `sam_<key>_<n>`), `site` (the SAM variant, e.g. `SA-5`), the place as `x` and `y` (DCS metres) or as `near` (airport name) with `bearing` (degrees) and `dist_m`, `levels` (a list of 1, 2, 3), optional `name`, `parent` (a red field id: the site is left out when that field does not exist at the level; it also gives the depth tier), `tier`, `jitter_m` |
| `raid_bearing_deg` | optional `[lo, hi]` degrees. The bearing from the carrier the Tu-22M3 carrier raid arrives on is drawn between these. Default `[20, 40]` (Caucasus). Pick open sea: a bearing over red land puts the raid on red's SAM rings (the planner then sends SEAD / Standoff DEAD first) |
| `max_raid` | optional `{"3": 12}`. The full Tu-22M3 carrier raid by level (bombers; escorts are half). Default 8 at Level 2, 16 at Level 3 (Syria uses the default: its 20-jet wing fields the 16). Keep it at or below the wing less the day's land strikes, or only a "desperate" raid can fly |
| `land_tu` | optional `{"3": 4}`. Tu-22M3 in one land strike by level (a 2-ship by default; the escorts are the usual 2 or one per two Tu-22M3, whichever is more). Syria L3 4 |
| `raid_from_base` | optional number of degrees, 0 to 45. The carrier raid arrives along the line from the carrier through the bomber wing's field, plus or minus this much (Syria 12); without it the bearing is drawn in `raid_bearing_deg` |
| `raid_grace_days` | optional whole number of days, 0 to 60 (default 0). Red stages no carrier raid while the day is at most this: Syria 7 (blue's surprise opening), Caucasus 3 (red needs time to find the carrier) |
| `map_box` | optional `{"x0": ..., "x1": ..., "y0": ..., "y1": ...}` in DCS metres (x0 south, x1 north, y0 west, y1 east). The edge of the map the carrier raid spawns on. Default: the terrain's own bounds from pydcs (wrong for Syria) |
| `era` | optional. `year` (the year shown for the campaign: a fixed label, month and day stay free) and the Era Equipment defaults of the New Campaign dialog: `a10_variant`, `f14_variant`, `link16` (true / false). Missing keys are Caucasus 2006: year 2006, `A-10C`, `F-14BU`, Link 16 on |
| `squadrons` | `id`, `name`, `aircraft`, `base` (the carrier or a blue field id), `count`, `callsign` (unique across the coalition). Optional `role`: `"havcap"` = an AI-only squadron that guards the AWACS and tankers. SQE moves a squadron to a field that can park it |
| `support_targets` | headquarters, fuel and ammunition: `parent` field, `id`, `name`, `kind` (C2, FUEL, DEPOT), `airport`, `dx`, `dy` offset in metres, `value` |
| `road_blue_airports` | airports on the blue side of the road net: they decide which side a road supply site belongs to |
| `front` | the ground war, see "The front" below |
| `tier_labels` | the depth labels shown for enemy assets (index 1 to 4). Required |
| `front_names`, `front_desc` | required by the loader, no longer shown anywhere |
| `climate` | optional. `sun_frac` and `rain_frac` (12 monthly values each: share of possible sunshine, share of days with precipitation), `wind_ms` (mean ground wind, 12 values), `fog` (chance of dawn fog, 12 values), `wind_from_deg` (12 values, the usual wind direction) with `wind_scatter_deg`, and `source` / `wind_from_source` (free text). Without it a mild generic climate is used. Drives Procedural weather |
| `sam_tier` | optional. Names the theatre's long-range SAM systems: `umbrella` (the systems whose reach covers their neighbours: the first thing a SEAD wave has to beat) and `gate` (the medium / long-range sites that get a Standoff DEAD and gate strikes), each a list of variants such as `["SA-5", "SA-10"]`. The reach and the margins of an umbrella system are in `sqe/samtier.py`. Missing: the Caucasus tier (the SA-10 as the umbrella; gate SA-2 / 3 / 6 / 11 / 10) |
| `title` | the operation name, shown in the app header and on the briefing's first line |
| `stories` | required. One story per level (`"1"`, `"2"`, `"3"`): `enemy`, `enemy_long`, `background` (a list of paragraphs), `intent`, `now` (a line per posture: Offensive, Holding, Under pressure ...) and `beats` (war-log lines for events such as a base falling or retaken) |

### The front

`front.chain` is the line of airfields from the red end to the blue end. Each node has `airport`, `name` and either `red` (an enemy field id) or `blue` (a friendly field id, the one that falls when the line reaches it). `front.leg_zones` is the number of sectors between each pair of neighbouring nodes (one number per leg). `front.rear_zones` adds quiet sectors behind the blue end. `front.stages`, `front.victory` and `front.counter` are keyed by level: the enemy fields that exist for the war, the fields that win it when taken, and the field whose fall brings the enemy counter-force. A level's chain is cut at its last stage field.

## Data files

Next to `<id>.json` in the pack folder SQE reads, when they exist: `<id>_geo.json` (the `geo` file), `<id>_relief.json` (ground height, 2 km cells), `<id>_sites.json` (the condensed ground, SAM and supply spots) and `<id>_roads_net.json` (the road net). They are built from a DCS terrain scan by `tools/sqe_scan.py`. A pack without them still loads: SQE falls back to a coarse coastline, a flat height estimate for low flights, and its own site placement.

Order matters in `wing_weight` and `red_fields` (they decide the order random choices are made in, so the same seed gives the same campaign).
SQE refuses a pack with a missing key and says which one.
